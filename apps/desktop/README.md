## 组织基础批

正式服务已按 `domain` / `application` / `infrastructure` / `connectors` 分责，保持 React → Tauri → Rust 的同一调用路径。Space 与上下文入口支持创建空间、可选分组、通用 Context 及移动位置；项目详情可显式关联/解除 Context。位置独立保存，移动不改变 Context ID/资料、不移动外部文件、不添加工具授权。

SQLite 当前 schema 为 6，可从 1～5 保留原 payload 升级。执行策略字段缺失时默认询问，升级不会产生自动授权。旧项目/对话缺少 `context_id` 时保持未关联，旧数据缺少任务记录时视为空，不猜测类别或伪造历史。版本门槛防止旧二进制写回时丢掉新增字段。普通对话与项目可分别关联 Context；基础 UI 未冻结，组织删除/共享/权限继承和完整对象图仍未实现。

正式路径：React → Tauri command → `wex-desktop-service` → SQLite / reqwest；PR #13 的请求由 `wex-api` 编码，PR #14 的可选流式请求由其 Decoder 解析后通过 Tauri 事件预览。普通 API 对话不调用 Flutter FFI。界面为基础功能入口，视觉与后续交互未冻结。

## Windows 启动

安装 Node.js 22 LTS、Rust stable、Visual Studio C++ 构建工具和 WebView2 后，在本目录执行：

```powershell
npm ci
npm run tauri dev
```

创建项目 → 在连接与服务中配置 DeepSeek/OpenAI 兼容 API 及多个模型 → 添加项目主 AI/施工/验证/审查成员 → 打开成员工作对话，或新建不依赖项目的普通对话。

每个成员拥有独立模型绑定和会话；请求附带当前项目目标与职责。主 AI 获取本项目全部任务（包含未分配任务）、成员名单及相关接续记录，施工/验证/审查成员获取当前分配给自己的任务与记录；不自动带入其他成员对话。任务卡可保存目标、范围、验收条件和多个成员。本批任务只保存草案，没有程序化派工或文件/终端执行，不能用 AI 的文字回答冒充实际施工、测试或审查。

API Key 保存在 Windows Credential Manager，SQLite 仅存不透明引用。数据位于 Tauri `app_data_dir`，目录由 Host 提供；不自动导入 Android 数据。`app.wex.pc` 为当前工程应用标识，安装包、正式签名及升级交付尚未验证。图标为技术占位资产，非最终视觉稿。

同一会话一次接收一个请求，不同会话的网络调用不持有全局数据库锁。重启后在途请求记为中断，不自动重发。API 已返回但落盘失败时可点击“重试保存结果”，只重试本地保存；关闭进程会失去尚未落盘的内存结果，重启后明确显示中断。

## 工具执行记录恢复（2026-10-25 本批）

非流式 Host 在派发前和结果返回前，将操作/尝试 ID、对话/回合 ID、状态及摘要写入本机 tool-receipts。对话页通过正式 tool_receipts command 读取并刷新本对话记录；失败回复和应用重启不删除记录。in_flight 表示已记录派发准备但未取得终态，不能推断为未执行或自动重试；succeeded 只代表执行成功，不代表独立核验。旧标记没有对话关联时保留原文件，不猜测归属。损坏或相互冲突的标记明确报错。

执行状态元数据保存在 tool-receipts；已完成工具的调用ID、名称、参数及返回正文另存入 tool-results，按对话/回合隔离。Host 在每项工具返回后、送回模型之前保存正文，后续批次项或模型请求失败不删除已保存结果。对话页可按回合查看/刷新正文，不会重新派发工具，也不会自动发送给模型。旧记录只有摘要时不能补造正文；保存失败明确提示可能已执行并要求核查。工具回执使用独立本地文件，不进入普通日志或凭证配置，Unix文件以0600创建。

非流式Host另接入tool-checkpoints：派发前保存原请求与待执行的assistant工具消息；整个批次取得回执后保存有序assistant/tool消息。检查点按对话/回合及原连接、模型、Endpoint、原请求内容绑定，不存凭证引用或API密钥。加载时核对序号、消息前缀和调用ID；最新记录未结算、序号缺口、损坏或绑定不符时拒绝退回旧快照。保存派发前检查点失败则不执行，保存结算检查点失败则不向模型继续。

服务层模拟HTTP测试已验证：工具回执保存后模型500失败，重新加载有序回执可向模型取得文本回复，工具回调仅执行一次。桌面代码已提供失败/中断回合的「发送已保存回执，恢复回复」入口：先只读检查完整检查点及当前连接、模型、Endpoint绑定；用户点击后将原回合标记为运行中，发送前再次复核连接与凭证引用，再从当前凭证库读取密钥。恢复使用保存的原上下文和完整工具回执，不重新访问原文件或派发工具。请求模型恢复时，原回合成功/正在运行、同对话已有请求、连接停用、绑定变化或存在待保存结果时拒绝受理；待保存结果仍使用原有重试保存入口。网络失败可重新检查恢复条件；结果保存失败优先重试保存，不再请求模型。旧的临时预览和输入草稿不会因恢复尝试而被清除。

最终完整回复另外保存到chat-replies，普通/流式发送和工具回复恢复均在写入SQLite前尝试保存。若SQLite落库失败并重启，对话页优先提供「恢复已取得的回复（不请求 API）」：核对原对话、回合和用户请求后写回原记录，不读取凭证、不执行工具，也不要求API连接启用。已有最终回复时拒绝再次请求模型；损坏备份明确报错，不自动降级成重新生成。备份失败但SQLite成功时保留正常成功结果；两处都失败时保留内存待保存结果并提示保持应用打开。

默认仍是只恢复回复；另可显式选择「恢复后继续工具流程」。该选项复用同一工具循环与现有审批，只把新模型回复提出的新工具请求送入审批，旧assistant/tool历史只回放给模型，不自动派发。新的pending/ready检查点从已校验游标后追加，不覆盖旧记录；未结算历史或旧游标冲突时停止，不退回旧快照重跑。普通与恢复循环在每次模型请求前复核当前连接/模型/凭证引用，新工具在Core派发前再次复核；已经派发的操作不追溯取消。GitHub配置不可用时不声明GitHub工具，实际GitHub请求仍检查其状态并明确报错，本地批次不依赖GitHub配置健康。

本批保留原型已有回合/批次/传输上限，并在历史无法再容纳完整新批次时提前停止派发，防止执行后才发现回执无法回传；这些不是新确认的永久产品限制。恢复后的工具循环已接通，本地目录持久授权、其他能力执行策略、未知结果核查后恢复、流式reasoning续传与完整自动调度仍未完成。服务层已验证数据库重启后在原回合保存恢复回复且不重复工具回调；Windows Host及桌面点击验收尚未完成，不能称为Windows实机交付。Rust恢复/隔离/冲突测试及前端构建按交付PR报告；Windows Host、凭证库和桌面交互仍需分别验收。

## GitHub 会话执行策略（本批）

对话页「本对话GitHub执行策略」分别配置读取、新建、更新的自动执行/询问后执行/拦截。默认询问；自动执行是在GitHub总开关和PAT可访问仓库范围内的用户授权，不启用连接、不扩展PAT、不限制成单仓库，也不授予本地文件/终端访问权。不同对话/能力不继承，角色或项目关联不能自动获得该策略。API停用时仍可配置偏好，执行时所有连接、参数、版本、资源及Core检查照常生效。每轮模型请求重新按当前总开关和策略声明工具，拦截的能力不提供给模型；实际派发仍再次复核。保存策略后同步刷新父页面快照，避免其他操作继续使用旧修订号。

策略由Rust应用层写入SQLite（schema6），每个对话/能力独立维护修订号，旧编辑冲突需刷新核对；修改不相关项目或其他策略不使当前批准失效。Host询问模式显示操作及内容，自动模式不再弹逐项确认，拦截模式不派发。派发前经当前API绑定、策略快照和GitHub凭证复核后才消耗Core批准。执行记录保存实际策略/修订号供核查，事后撤销不重写历史；已派发操作不追溯取消。

本批仅接入当前三项GitHub能力。本地目录注册表仍是进程内可信身份，保存路径不能代替重启后的有效绑定；本地持久授权、读写/通用命令能力及其他策略接线仍待后续完成，不能把GitHub策略称为完整权限体系。Linux自动化验证和前端构建按PR记录，Windows原生审批/凭证与真实GitHub操作尚未验收。

前端`npm test`实际运行React DOM交互（模拟IPC），覆盖自动偏好正确作用域且不启用连接、冲突不静默覆盖/显式刷新、父快照刷新失败时保留已保存策略、切换对话后的迟到响应隔离；这不替代Tauri/Windows实际点击验收。
