# WEXPC 0.1.1 前／中／后三阶段重排研究（2026-10-27）

**状态：研究建议，尚未冻结或替换当前 P1～P6 施工计划。版本仍为 0.1.1。** 本文件记录用户提出的新优先级：前期先建立通用 Space 管理、Context 自由组合、角色／Agent、API、普通对话与连接器；中期再评估具体工作模式及模板；后期完成开发模式的真实持续执行闭环。中后期具体施工包和验收仍待前期架构审查。

## A. 已确认的边界和重新排序原因

过早把“软件开发模式模板”当作 Context 通用本体，导致 Agent 强制 project_id、固定 role、项目会话和任务成员校验的绑定。通用 Context 应可仅选择一个资源地址、一个 Agent 与搜索，也可选择其他连接方式与功能；模板是预设组合，不是 Context 创建或使用前置。纠偏采用渐进式兼容，不批量删除旧数据、代码，不新建权限引擎或 Dispatcher。

当前实施文档 P1～P6 是按开发闭环划分的施工包，与本次用户希望的“前／中／后”产品能力先后顺序不同。两者需重新映射，不能仅改名称就误以为软件开发模板可先于通用连接/组合成熟。

## B. 三阶段初步方案（待核对）

| 内部分期 | 目标 | 重点 | 退出条件／限制 |
|---|---|---|---|
| 前期（首先研究和收敛） | **无模板也能使用的 WEX 核心** | Space/Group/Context 组织与可选资源、连接实例/工具能力、Agent/职责、普通 Conversation、API/模型连接、连接器目录、最小调用与授权/回执 | 用户可手动建立极简 Context，勾选或取消可用能力，绑定 Agent 或独立会话并真实完成授权范围内的搜索／API／基础工具调用；模板及项目任务不是前置。现有工具如搜索尚未保证已接通，实际验收按可用连接器实施 |
| 中期（不抢先实现） | 基于已验证通用组合构建特定工作模式 | 软件开发模式的轻项目、岗位默认组合、项目 Task、成员与 Context 的关系；**模板引擎是否在本期实现及深度待研究** | 模式默认组合可更改，不污染通用 Context；保留 0.1.1 已确认的项目管理/多 Agent 施工要求 |
| 后期（完工闭环） | 对软件开发模式做持续执行及 Windows 验收 | Dispatcher 实际派发/并发、文件/终端/Git/GitHub、独立审查验证、可恢复回执、Windows 安装与真实工程回归 | 按正式基线验收，工具成功≠审查≠验证≠最终完成；未知副作用不得盲目重试 |

说明：表中“中期模板”指可选的简单工作模式组合；**完整模板管理器／模板编辑器／版本迁移／继承系统不应因为这次分期就被默认纳入 0.1.1**。通用 Dispatcher、连接器和权限的接口设计必须在前期提前建立，后期是完成实际复杂执行链路，不是最后才建底座。

## C. 前期需要研究和收敛的七项契约

1. **空间组织**：Space / 可选 Group / Context 的稳定身份、主要展示位置及跨 Context 关联，不能让位置等于授权。
2. **可选组合**：资源、Agent、连接实例、工具/能力、其他 Context/项目的关联表示及可随时勾选/取消；不将地址字符串膨胀为万能引用。
3. **能力发现**：Connector 实例、接入机制、可提供的能力、启停／参数／范围与本次选择独立；不假设一连接只一种能力。
4. **角色体系**：独立 Agent 身份、Duty/工作范围、模型选择、会话与执行权限分离；清理固定 project_id 语义而保留兼容数据。
5. **通用对话**：Conversation 不要求项目/Task/Agent；既能直接选 API，也能按当前有效配置选择 Agent 与工具。
6. **授权与数据外送**：已引用/已勾选 ≠ 已授权；Host 权限、外部 API 数据边界与执行策略分离，并阻止错范围资料自动发给模型。
7. **可追溯调用**：操作身份、有效范围、连接/能力、执行结果及未知状态；无需软件开发项目 Task 才能有回执。

## D. 用例驱动的前期验收研究

- **极简研究**：Context 仅有 URL + Agent + 搜索；不创建 Project/Task/Lead/Reviewer 即可使用选定连接，在实际授权下查询，变更工具连接不改变 Context 身份。
- **纯聊天**：无项目、无模板的独立 Conversation，用户选择 API/模型聊天，可选是否引用 Context。
- **多范围角色**：同 Agent 在两个 Context 承担不同 Duty；资料、提示和授权不串用。
- **无 AI 组织**：没有连接／Key，用户仍可创建、移动和查看 Context 及资源引用。
- **软件开发兼容**：旧项目和任务能打开，且新通用配置不导致旧记录丢失；不得把临时兼容回退作为永久执行授权。
- **撤销/失效**：移除 Context 对工具的选择、禁用 Connection、撤销权限三种动作语义不同；已发生外部写入按回执核对。

## E. 与当前施工计划的关系与待裁决

既有 P1～P6 聚焦本地开发工具闭环优先，这和新提出“先建立通用基础”的顺序不同。**后续需在审查 main 实际源码完成度后重排工作包与验收前置依赖**；不能在未核实的情况下声称旧施工批次被取消。现有本地文件、API、GitHub、回执、安全机制仍是可复用能力，允许继续修复关键缺陷，但不得重新引入软件开发模式作为通用 Context 的依赖。
