## B. 拟写入主基线的最小语义文案（待接受后方可修改）

### §2.1：Space / Context 的组织、分类与引用

> Space、可选 Group 与 Context 是 WEX 的组织及呈现结构。个人、工作、公共及未来组织等为可扩展的组织类别，类别本身不产生系统账号、共享或权限。Context 能引用独立存在的会话、任务、连接、文件和服务资源，不因移动或分类变更而自动转移数据所有权或扩大授权。当前版本不要求实现完整的组织管理体系。

### §2.2：恢复原生 AI 对话

> WEX 原生 Conversation 是独立交互对象，不要求先创建项目、任务卡、岗位或施工 Agent。用户可以从 Context 直接进入普通对话，选择可用 API 模型、角色或内部 Agent 配置。交互对象、模型、岗位、执行身份与实际授权分离。默认对话入口可以按需创建会话，无须永久预造空聊天记录。

### §2.3 / §4.1：外部会话所有权和最小适配

> DSH 等外部 Agent 客户端拥有其内部 Session、消息及工具执行历史。WEX 不将外部会话全文默认复制为自己的 Conversation。WEX 管理自身连接、外部引用、任务投递及接收状态、成果定位和独立核验记录；需要复盘时可在外部接口支持且权限允许的情况下按需读取。WEX 对接协议只约束跨系统边界，不接管外部 Agent 内部工具循环或权限实现。

### §2.7.2：工作范围授权、工具自由组合

> 用户可以按工作目标、资源/账号作用域、操作范围和执行策略授权。AI 在有效授权及真实 OS、沙箱与服务端权限限制内可自行组合工具，不要求事前列举全部执行流程，也不因每次工具调用重复审批。新的范围、高风险外发、重大不可逆副作用等按适用策略另行处理。外部客户端的实际安全边界须独立核实，不能仅以 WEX 提示或 UI 标记推断其已被隔离。

### §2.7.3：细粒度会话交互

> 段落选中/引用、采纳或拒绝观点、局部修订与分支讨论、从内容创建 Task、批准实际写操作和独立验收是不同语义。一个序列项被勾选不意味着自动创建任务、允许工具执行或验证通过。必要状态与来源分别记录，具体 UI 与持久化结构尚未冻结。

### §4.1 / §5：原生执行与外部复用并存

> WEX 保留独立的 API、文件、终端、Git/GitHub 等基础服务；外部 Agent 可按需接入、委派和读取结果，但不是原生能力的先决条件。外部不可用时可以考虑原生替代；若原任务状态不明或操作可能产生副作用，不得未经核对自动重新执行。

## C. 两项潜在文字冲突

**C1 — §5.1.3 全链路追溯：**现行规则要求从 Task 追溯会话、操作意图、工具请求和回执。此要求对 WEX 自有执行链成立；不能直接推导出必须获取 DSH 每一个内部工具事件。建议增加“WEX 自身边界事实”适用范围。

**C2 — §2.7.1 外部 Agent 适配：**外部 Agent 需要具备 WEX 可依赖的发送/响应/定位边界，不需要改造其内部工具协议。能否支持对指定 DSH Session 发送、查询、回看，需真实接口测试，当前不能宣称已完成。

## D. 不改动的正式产品目标

- **WEXPC 0.1.1 不缩水**：普通聊天、基础 Space/Context、API/模型、本地文件/终端/Git/GitHub、轻项目、主 AI 分工、程序化 Dispatcher、多 Agent 真实施工与独立验证、恢复接续仍保留。
- 角色与岗位可兼任，不等于资源授权继承。
- 组织/共享平台、全量外部 Session 同步、高级权限规则引擎、画布与多视图完整 UI、跨环境委派深化均暂不因这份提案升格为 0.1.1 必须实现。
- 不修改源代码、API 函数签名或持久化数据库，仅提交讨论材料。
