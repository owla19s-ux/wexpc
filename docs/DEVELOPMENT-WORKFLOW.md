## 临时暂停云端验证：2026-10-24 至 2026-10-31（北京时间）

用户已明确已有约6—8美元账单，暂停期内不触发、重跑或手动运行任何GitHub Actions。源码继续施工，提交统一使用 `[skip ci]`（包括PR更新/合入时生成的提交信息）；不要借验证工作流配置触发云端试跑，也不构建云端安装包。工作流自动PR入口临时注释，保留手动入口仅供暂停期结束后评估使用；不设置定时恢复。

- 大肥鱼：在手机环境配置可实际运行的Rust工具链；能够在手机完成的模块测试、模拟服务和实际调用本地完成，报告环境、命令、Commit和结果，未运行不能推断通过。
- 当前Work环境：可运行的Rust测试、fmt/clippy、前端类型检查/构建在本地执行；没有手机测试结果时不代称手机已通过。
- 两边均无法运行的Windows Host/平台测试、桌面交互、签名安装包及模拟器等：代码可继续完成，按源码Commit登记NOT_RUN、缺少环境/工具及11月1日后待执行命令；保留最近已验证源码作为基准，不把旧结果套到新改动。
- 2026-11-01以后才可集中评估云端验证；不因日期到达自动恢复所有workflow或重跑每个历史提交，只对整合后的目标提交运行必要检查。
- 旧WEX同样暂停云端验证；涉及其分支的提交也须跳过CI，不主动触发旧工作流。当前连接器缺少仓库级disable接口，不能宣称WEX/WEXPC全部分支已全局停用；其他AI须在各自分支遵守暂停及skip规则，仓库级设置需通过具备相应权限的入口处理。

此前“源码PR自动验证”的规则在暂停期内由本节暂时覆盖；原验收目标和后续平台证据要求保留。

本节是当前开发WEXPC的操作依据，不是产品内主AI/施工AI的调度协议。按实际环境分配验证，不以“手机”或“工作模式”的名字推断能力，也不把手机本地测试等同于Windows验收。环境改变后直接更新本节，不另建一套平行规则。

API实现的目标目录为 `crates/wex-api/**`，由大肥鱼在正式接手后独占（含模块自身Cargo.toml和测试）；现有 `crates/wex-desktop-service/src/connectors/**` 由Work负责桌面薄适配。Core准备业务请求并裁决权限/派发工具，API只负责协议请求、事件和调用意图，不自行授权或运行工具。API所需密钥由Host安全读取后在调用边界提供，不把Windows Vault搬入手机可测模块。

**当前实施状态**：`wex-api`目录、可编码接口与可运行模块起点尚未落地；`feat/api-protocol`分支尚未创建，未宣称已经派发。大肥鱼现在可先配置手机环境。Work先完成接口和工作区/依赖准备、验证最小契约测试可运行，再登记实际交接Commit；交接之后Work不同时修改该模块。抽取独立crate是为隔离桌面/平台依赖，不为增加空模块或替代成熟基础组件。

### 两边的日常操作

大肥鱼先提交一次环境验通结果（不是安装计划）：

```sh
uname -sm
cargo --version
rustc --version
rustc -vV
git rev-parse HEAD
```

再运行一个能实际编译、执行并断言结果的Rust测试，以及本机回环HTTP测试，确认编译器、运行库、socket和必要C/TLS依赖。若失败，记录精确命令和脱敏错误；能转到Work本地验证的先转交，不转去触发Actions。

`wex-api`起点交接、依赖和锁文件就绪后，大肥鱼的模块验证命令才是：

```sh
cargo fmt -p wex-api -- --check
cargo test -p wex-api --locked
cargo clippy -p wex-api --all-targets --locked -- -D warnings
```

当前crate不存在时不要求运行这些命令，也不能把缺少crate当作手机工具链失败。新增依赖由双方先核对手机目标兼容性；确需试验时可在隔离副本验证，把依赖清单交Work统一更新共享配置/锁文件，避免两边争改根锁文件。

Work当前已确认工具在 `/root/.cargo/bin`，但默认PATH未包含它；可使用绝对路径，或在当前Work shell先执行下列设置。手机必须使用其实际安装位置，不照抄Work路径；“PATH找不到”不能直接认定工具未安装。

```sh
export PATH="/root/.cargo/bin:$PATH"
```

Work按实际改动先跑相关包/测试，批次集成时再运行必要的整体检查：

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml -- --check
```

前端在 `apps/desktop` 目录执行 `npm ci`（依赖变化或环境缺失时）与 `npm run build`。命令成功只证明对应检查；Rust平台条件编译未执行的Windows用例、缺失桌面依赖时未执行的Host编译，必须单列NOT_RUN。手机测试通过后由Work做受影响集成验证，不要求双方机械地重复全部测试。

### 证据交接、失败处理和待验证项

每批结果附以下信息，写入对应PR/工程交接记录；长期规则仍维护在本文：

```text
模块/任务：
施工分支、源码Commit、集成Commit（如有）：
实际执行环境、OS/架构、Rust/Node及关键依赖版本：
验证类别：单元 / 模拟服务 / 真实服务 / 编译 / UI交互 / 模拟器 / 真机
实际命令、目标平台、结果：PASS / FAIL / NOT_RUN
日志或产物位置（不含密钥/私人数据）：
未执行项目、原因、后续命令及执行环境：
```

- 测试失败先定位源码、依赖或环境问题，修复后只重跑受影响项并完成必要回归；缺环境转移可运行的测试，不以暂时无环境删除产品功能或弱化验收。
- 没有手机日志就标手机NOT_RUN；Linux测试里被cfg跳过的Windows测试不计为Windows通过。真实API、模拟HTTP、模型文字报告及真实工具执行回执分别报告。
- 仅API模块通过不能认定桌面已接入；Work需检查依赖、适配、配置、权限、调用、结果和可操作界面，未接线项保留为缺口。
- 当前待补的平台类证据包括Windows实机窗口/凭证读写、安装交付、实际本地工具与模拟器；Windows CI可补编译和自动测试，不能代替所有交互/真机验收。后续源码影响这些部分时在对应PR增列具体提交及待测命令。
- 11月1日后按待验证清单选择整合目标提交，先查是否已有同源码同环境证据，再决定必要云端Job；不重跑一周内每个中间提交，也不默认恢复日常Windows自动检查。

## 每批开工

1. 核对用户最新明确要求、PC 基线相应章节与原 WEX 文档的适用范围；标明已确认、讨论/候选、已实现、已验证和废弃。冲突指出具体位置，不能选择容易实现的一版。
2. 查 WEXPC 最新 main、开放 PR/分支、目标源码和相关 Actions。确认当前 HEAD 与工作分支、已有独有成果和真实差距；不得按旧交接总结重复施工。旧 WEX 只读追溯，不把改动提交到旧仓库。
3. 说明本批依据、实际差距、交付后用户可操作行为和验收方式。常规实现细节可自主决定；范围、权限、UI、模块选型与阶段目标不得暗改。长任务可分批，但保留完整目标和剩余项。
4. 代码变更核查实际依赖、配置、调用路径、权限、结果及 UI 接线；下载源码、声明依赖、模拟响应、单文件测试都不等于真实集成或完整能力。

## GitHub 分支、PR 和 Actions

- 在 WEXPC 使用有明确范围的分支和 PR；继续已有 PR 时先核对 head/base 和最新提交。不要强推 main；合并/清理分支前核对独有提交、审查状态和最终测试 SHA。
- 文档规范直接修订权威正文及冲突入口，不增添多份互相矛盾的“补充版”。PR 的文档修改不等于代码实现。
- 查 Actions 从仓库运行列表、Job 和失败日志开始，不反复向用户索取 Run ID。区分未触发、排队、取消、环境失败、编译失败、测试失败。
- 批次内相关提交集中验证；暂停期内所有源码/文档提交都跳过Actions，当前开发分支只保留手动入口且本期不使用。暂停期结束后再按实际影响评估触发规则，不沿用旧自动检查频率。需要安装包或实机体验时才做相应构建。
- 不提交密钥、私人数据或未审查的构建产物。凭证不能进入模型上下文、日志、PR 文本或普通数据库。
- 报告 PR/Commit、改动路径与验证证据；自动化结果必须对应实际交付 SHA。分别列代码、自动化、真实 API/GitHub、Windows 构建和 Windows 实机状态；未运行明确标注。
