# WEXPC 项目说明

> 更新：2026-10-26。本文是项目定位与阅读入口，不代替正式产品基线，也不声明功能已经交付。

## 项目定位

WEX（维加）是以**联通**为上层语义的跨系统工作组织、连接、调度和交互系统，不只是 AI 聊天客户端。WEXPC 是当前 **Windows PC 优先**的研发与交付仓库；Android 暂缓作为交付主线，但其成熟设计与通用实现可按需参考。两个仓库独立维护，不能从同名版本推断功能或验证状态一致。

WEX 以 Space → 可选 Group → Context 组织不同领域的工作，连接模型 API、GitHub、本地文件/进程/Git、浏览器及可选外部 Agent 等能力；组织对象、连接实例、授权、任务状态、调度与真实执行证据相互区分。上层“联通”不要求重命名现有 Connector、Dispatcher、Executor 等代码模块。

## 0.1.1 的目标

首版需要可实际使用的普通 AI 对话、基础 Context/轻项目、API 与模型配置、角色/岗位及独立 Agent、受控本地工具与 Git/GitHub、主 AI 分派、程序化 Dispatcher、多 Agent 施工、审查验证与可恢复任务状态。目标使用场景是在 Windows 上持续开发 WEXPC 和 WEX Android，并基于真实工具结果继续工作。

**目标不是完成状态。** 代码实现、Linux 自动化检查、Windows 构建与真实 Windows 安装/运行应分开登记；具体缺口和验收以产品基线、施工计划及相应提交证据为准。

## 架构职责概览

- **Space / Group / Context**：组织与引用工作信息，不因引用自动取得资源授权；普通对话可以独立于项目任务存在。
- **Connection / Connector / Capability**：管理连接实例、接入机制及可声明能力；一个连接可提供多种能力，安装/认证/可见不等于授权或可用。
- **权限与执行服务**：在实际 OS/服务边界内检查授权、执行并登记操作及回执；既支持原生 API/工具，也可复用外部能力。
- **Task / Dispatcher**：Task 领域保存权威任务状态；Dispatcher 负责确定性队列、路由、派发、占用和恢复，不代替 AI 作技术方案判断。
- **原生与外部 Agent**：WEX 自有工具链负责自身操作证据；外部 Agent 内部会话和工具历史由外部系统持有，WEX 仅追踪自身投递、接收、成果位置与独立核验。不能假定 WEX 内部资源锁约束外部进程。
- **审查与验证**：工具返回成功、模型报告完成和独立 Verify 通过是不同事实；未知副作用不自动重放。

以上是方向性边界。具体接口、对象字段、数据库、插件隔离选型，以正式基线中标注的确认程度为准；`DECISIONS.md` 的 DRAFT 内容不自动升级为确定实施要求。
